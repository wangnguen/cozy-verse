### 1.14 Đồng bộ thiết bị

Không cần đăng nhập hay tài khoản. Các thiết bị kết nối với nhau bằng **mã đồng bộ**. Dùng Cloudflare (Workers + D1, gói miễn phí), cần thêm một Worker nhỏ làm API, deploy chung project. GĐ1–2 vẫn chạy hoàn toàn trên trình duyệt.

- **Bật đồng bộ** trên một máy → app tạo mã đồng bộ, hiển thị dạng QR và chuỗi ký tự.
- **Máy khác** quét QR hoặc nhập mã → dùng chung dữ liệu.
- **Đồng bộ:** cài đặt, profiles, bản phối, cảnh yêu thích, cảnh dạng link, playlist dạng link, tasks, notes, lịch sử phiên, thống kê, XP / streak / thành tích.
- **Không đồng bộ:** file nhạc, ảnh, video tải lên từ máy (chỉ có trên máy đó).
- **Lần đầu kết nối:** gộp dữ liệu đang có trên máy với dữ liệu đã đồng bộ.
- Mất mạng vẫn dùng bình thường; có mạng lại thì tự đồng bộ.
- Timer đang chạy hiện trên thiết bị khác (ví dụ bắt đầu trên máy tính, xem trên điện thoại).
- **Quản lý:**
  - tắt đồng bộ trên một máy;
  - đổi mã (máy nào còn dùng mã cũ sẽ bị ngắt);
  - xoá toàn bộ dữ liệu đã đồng bộ.
- **Lưu ý:** mã đồng bộ là chìa khoá duy nhất. Ai có mã là xem được dữ liệu, nên không chia sẻ mã. Nếu mất mã và mất hết thiết bị thì không lấy lại được dữ liệu đã đồng bộ.

## 3. Kiến trúc kỹ thuật

### 3.1 Công nghệ

| Hạng mục | Chọn |
|---|---|
| Framework | React + Vite, build ra web tĩnh (SPA), pnpm |
| Ngôn ngữ | TypeScript strict, alias `@/` trỏ tới `src/` |
| Định tuyến | Không dùng router: `/` là `index.html`; `/embed` (GĐ4) là trang HTML thứ hai (`embed.html`) của Vite; widget đang mở lưu trên URL (`?panel=timer`) |
| State | Zustand, mỗi feature một store |
| Styling | Tailwind CSS v4, token đặt trong `styles/variables.css` |
| Component nền | shadcn/ui (Radix), mỗi component một file trong `components/ui/` |
| Animation / icon | Motion / Lucide |
| Lưu trên máy | IndexedDB (Dexie) + localStorage |
| Validate | Zod |
| Test | Vitest |
| GĐ2 | Tiptap (notes), dnd-kit (kéo thả), manifest trong `public/` + service worker (vite-plugin-pwa hoặc tự viết) để cài app và chạy offline |
| GĐ3 | Cloudflare Workers (API) + D1 (SQLite); thư viện tạo và quét QR cho mã đồng bộ |
| GĐ4 | three + @react-three/fiber + drei, chỉ tải khi vào phòng 3D |
| Hosting | Cloudflare Workers (static assets): đăng thư mục `dist/` do Vite build ra |

- **Web tĩnh, chạy hoàn toàn trên trình duyệt:** Vite build ra file HTML/JS/CSS tĩnh, không cần server. App không cần SEO và không render phía server, vì màn workspace cần localStorage, IndexedDB và Web Audio. Vì vậy không dùng framework có server như Next.js, tránh được các giới hạn của chế độ xuất tĩnh và cấu hình đơn giản hơn.

### 3.2 Triển khai trên Cloudflare (gói miễn phí)

| Phần | Dùng | Ghi chú |
|---|---|---|
| Code web (thư mục `dist/`) | Workers static assets | Có sẵn HTTPS + CDN; chế độ SPA: đường dẫn không tồn tại thì trả về `index.html` |
| Âm thanh môi trường, ảnh, poster, video loop nhỏ | Workers static assets (thư mục `public/`) | |
| Video cảnh lớn, nhạc | YouTube nhúng | Không tốn dung lượng của Cloudflare |
| API đồng bộ | Workers (GĐ3) | Chạy chung một Worker với web, nên cùng domain và không phải xử lý CORS |
| Dữ liệu đồng bộ | D1 (GĐ3) | SQLite trên Cloudflare |
| Video lớn tự host (nếu cần) | R2 | Chỉ dùng khi thật cần, ưu tiên YouTube |

**Giới hạn gói miễn phí và cách giữ trong giới hạn**

| Dịch vụ | Giới hạn | Cách giữ |
|---|---|---|
| Static assets | Không giới hạn lượt tải; tối đa 20.000 file, 25 MiB mỗi file | Nén video loop dưới 25 MiB; file âm thanh loop ngắn |
| Workers | 100.000 request mỗi ngày, 10 ms CPU mỗi request | Tải file tĩnh không tính vào giới hạn này; đồng bộ theo lô và chỉ gọi API khi cần |
| D1 | 5 GB; 5 triệu dòng đọc, 100.000 dòng ghi mỗi ngày | Chỉ ghi phần thay đổi; chỉ kéo về phần mới kể từ lần đồng bộ trước, không đọc lại toàn bộ |
| R2 | 10 GB lưu trữ, không tính phí băng thông tải xuống | |

- Deploy bằng `wrangler deploy`, hoặc nối GitHub để tự deploy mỗi lần push. Mỗi bản deploy có link preview riêng.
- Dùng domain miễn phí `*.workers.dev`, hoặc gắn domain riêng.

### 3.3 Nguyên tắc kiến trúc

```
app/        (diem vao cua tung trang, mong)
  |
  v
workspace/  (ghep man chinh, flows)
  |
  v
features/   (khong import lan nhau)
  |
  v
components/    shared/    config/
```

- **Chiều phụ thuộc** `app → workspace → features → components / shared / config`. ESLint chặn import sai chiều.
- **`app/` chỉ chứa điểm vào của từng trang HTML** (`main.tsx` gắn React vào `index.html`, `App.tsx`). Để mỏng, chỉ gọi vào `workspace/` hoặc feature.
- **Feature không import lẫn nhau.** Luồng nào cần nhiều feature thì đặt ở `workspace/flows/`.
- **Mỗi feature có public API** (`index.ts`) export component, actions và sự kiện. Bên ngoài chỉ import qua đó, không import sâu vào trong.
- **`components/` không biết gì về feature.** Layout nhận nội dung qua slot.
- **Lớp `api/` trong mỗi feature** tách nguồn dữ liệu khỏi UI. Tới GĐ3 thêm đồng bộ mà UI không phải sửa.
- **Logic thuần** (engine timer, kênh âm thanh, tính thống kê) không import React, để dễ test.
- **Zustand store theo feature**, đọc bằng selector. Timer cập nhật mỗi giây cũng không làm re-render cả cây.
- **Kiểu dữ liệu dùng chung** nhiều feature đặt ở `shared/types/`, mỗi kiểu một file.
- **Đặt tên:** file chứa component đặt PascalCase giống tên component (`WorkspaceRoot.tsx` → `WorkspaceRoot`); hook và file còn lại camelCase (`usePanel.ts`, `applyProfile.ts`); file điểm vào trong `app/` giữ tên thường (`main.tsx`, `embed.tsx`); thư mục viết thường.
- **Chỉ tạo thư mục khi có code thật.** Ví dụ `devices/`, `sync/`, `worker/`, `room3d/`, `embed/` chỉ tạo khi tới giai đoạn tương ứng.
- **`worker/` (GĐ3) tách riêng khỏi `src/`.** Worker chỉ dùng chung kiểu dữ liệu trong `src/shared/types`, không import code giao diện.

**Khi nhiều feature cần phối hợp**

1. **Feature phát sự kiện, `workspace/` lắng nghe.** Timer phát "phiên tập trung xong" → `workspace/flows` lưu phiên vào stats và cộng XP / streak ở progress.
2. **`workspace/` gọi actions của nhiều feature, rồi truyền xuống qua props / slot.**
   - Luồng "áp profile" đổi cùng lúc cảnh, âm thanh, nhạc, cấu hình timer (áp dụng từ phase sau, không reset phiên đang chạy).
   - Ô chọn profile nhận luồng này qua props.
   - Widget timer nhận ô chọn task (của tasks) qua slot.
3. **Hạ tầng dùng chung để trong `shared/`.** `shared/audio` là nơi scenes, sounds, music cùng đăng ký kênh âm thanh, và mixer đọc danh sách kênh từ đây. `shared/youtube` dùng chung cho scenes và music.

### 3.7 Âm thanh

```
 ambient file  --tai + giai ma-->  kenh file loop  --gain--+
 noise (tu sinh) --------------->  kenh noise      --gain--+--> volume tong --> loa
 nhac tren may ----------------->  kenh media      --gain--+
 nhac YouTube  ----------------->  kenh YouTube    (chinh volume qua API cua player)
 am thanh canh ----------------->  kenh YouTube    (chinh volume qua API cua player)
```

- Chỉ có một `AudioContext`, khởi động khi người dùng bấm "Bắt đầu".
- **Ambient:** phát lặp liền mạch bằng Web Audio.
  - Chỉ tải file khi âm đó được bật, giải phóng khi tắt lâu.
  - File loop ngắn 30–60 giây.
- **Noise** white / pink / brown: sinh ngay trong trình duyệt, không cần file.
- **Bật/tắt và đổi profile:** volume tăng/giảm dần, không đột ngột.
- **Nguồn YouTube** không đi qua Web Audio, nên volume thực = volume kênh × volume tổng.
- **Nhạc từ máy:** lưu file vào IndexedDB, phát qua Web Audio.
- **Spotify / SoundCloud (GĐ2):** dùng trình phát nhúng chính thức. SoundCloud chỉnh được volume; Spotify chỉ bật/tắt được.
- **Khoá âm thanh** (profile IELTS Listening): tắt mọi kênh và chặn phát lại.
- **Mixer:** liệt kê mọi kênh đã đăng ký, chia 3 nhóm: Môi trường / Nhạc / Cảnh.

### 3.8 Timer

```
           start              pause
  [idle] --------> [running] --------> [paused]
     ^               |    ^               |
     |               |    +---- resume ---+
     |               |
     |               | den thoi diem ket thuc
     |               v
     +---------- [completed] ---> phat su kien "phien xong", chuong,
       sang phase tiep              thong bao, tinh phase tiep theo
       (tu start neu bat)
```

- **Lưu thời điểm kết thúc, không lưu bộ đếm.** Thời gian còn lại luôn tính bằng thời điểm kết thúc trừ giờ hiện tại, nên không bị lệch.
- **Tab bị ẩn:** trình duyệt làm chậm bộ đếm giờ. Cách xử lý:
  - đếm trong Web Worker;
  - kiểm tra lại khi quay về tab;
  - hẹn chuông bằng Web Audio.
- **Reload trang:** lưu trạng thái timer, mở lại thì chạy tiếp. Nếu đã quá giờ thì tính là phiên hoàn thành.
- **Mở nhiều tab:** chỉ một tab được phát chuông và ghi phiên (Web Locks + BroadcastChannel).
- **Chuỗi phase:** tập trung → nghỉ ngắn, hoặc nghỉ dài sau mỗi N vòng → tập trung…
- **Flow mode:** dùng chung engine, đếm lên thay vì đếm xuống.

### 3.9 Lưu trữ

| Dữ liệu | Nơi lưu |
|---|---|
| Cài đặt, vị trí widget, cảnh / mix đang dùng, trạng thái timer | localStorage |
| Tasks, projects, notes, thư mục, lịch sử phiên, profiles, cảnh tự thêm, playlist | IndexedDB |
| File nhạc / ảnh / video tải lên từ máy | IndexedDB, không đồng bộ |
| XP, streak, thành tích | Tính lại từ lịch sử phiên |
| Cấu hình chia sẻ | Link (phần `#` của URL) |
| Dữ liệu đồng bộ (GĐ3) | Cloudflare D1 |

- Dữ liệu có phiên bản. Khi đổi cấu trúc dữ liệu thì tự chuyển dữ liệu cũ sang cấu trúc mới.
- Mọi bản ghi cần đồng bộ đều có id, thời điểm cập nhật và cờ xoá mềm.
- Xin trình duyệt lưu trữ lâu dài, để dữ liệu không bị tự xoá khi máy thiếu dung lượng.

### 3.10 Chia sẻ & backup

- **Link chia sẻ:**
  - Chứa cảnh, bản phối, cấu hình timer, kênh nhạc. Không chứa tasks, notes hay file trên máy.
  - Khi mở link, mọi giá trị được kiểm tra hợp lệ trước. Người dùng xem trước rồi xác nhận mới áp dụng.
- **Backup:**
  - Xuất một file chứa cài đặt và dữ liệu (trừ file media).
  - Khi nhập: kiểm tra hợp lệ, rồi chọn *Thay thế* hoặc *Gộp*. Khi gộp, bản ghi nào cập nhật sau thì thắng.

### 3.11 Đồng bộ thiết bị (GĐ3)

```
 May tinh / dien thoai                                 Cloudflare
 feature api -> IndexedDB -> hang doi --day len--> Worker --> D1
                    ^                                          |
                    +------------- keo ve thay doi ------------+
```

- **IndexedDB vẫn là dữ liệu chính.** D1 chỉ là bản sao trên mây, nên mất mạng vẫn dùng bình thường.
- **Không sửa lớp `api/` của feature.** Mỗi lần ghi, `shared/sync` đưa thay đổi vào hàng đợi.
- **Mã đồng bộ:**
  - Bật đồng bộ → Worker tạo một "không gian đồng bộ" và trả về mã: chuỗi ngẫu nhiên đủ dài để không đoán được, hiển thị chia nhóm cho dễ nhập, kèm QR.
  - Mã lưu trên máy và gửi kèm mỗi request qua HTTPS.
  - Server chỉ lưu bản băm của mã, nên lộ database cũng không lộ mã.
  - Giới hạn tần suất tạo mã mới để tránh bị lạm dụng.
  - Có thể thêm: mã hoá dữ liệu ngay trên máy bằng khoá suy ra từ mã trước khi gửi lên, khi đó server chỉ giữ dữ liệu đã mã hoá.
- **Thời điểm đồng bộ:** khi bật / kết nối đồng bộ, khi mở app, khi quay lại tab, khi có mạng lại, và định kỳ khi tab đang mở.
  - Bước 1: đẩy hàng đợi lên theo lô, một request gửi được nhiều thay đổi.
  - Bước 2: kéo về các thay đổi kể từ lần đồng bộ trước. Server cấp một con trỏ tăng dần để đánh dấu đã đồng bộ tới đâu.
  - Bước 3: gộp dữ liệu, bản nào cập nhật sau thì thắng.
- **Tổ chức dữ liệu D1:** mỗi loại dữ liệu một bảng (tasks, notes, phiên, profiles, cài đặt…), mỗi dòng gắn với một không gian đồng bộ. Worker chỉ trả dữ liệu của không gian ứng với mã gửi lên.
- **Timer giữa các máy:** mỗi không gian đồng bộ có một dòng trạng thái timer, chỉ cập nhật khi start / pause / kết thúc. Máy khác thấy trạng thái mới khi mở app, khi quay lại tab, hoặc ở lần kéo định kỳ. Nếu muốn cập nhật tức thì, sau này có thể thêm Durable Objects + WebSocket.
- **Lần đầu kết nối:** máy mới đẩy dữ liệu đang có lên, kéo dữ liệu đã đồng bộ về, rồi gộp lại.
- **Không đồng bộ:** file media tải lên từ máy.
- **XP / streak / thành tích:** tự tính lại từ lịch sử phiên sau khi đồng bộ.
